# Interview Preparation

This repository is designed to generate interview questions from the actual projects rather than memorized generic answers.

## Universal project questions

1. What problem did you solve?
2. Who would use the system?
3. What is the input?
4. What is the output?
5. What assumptions did you make?
6. How did you validate the data?
7. How did you prevent leakage?
8. Why did you choose the baseline?
9. What metrics did you use?
10. Why are those metrics appropriate?
11. What are the biggest failure modes?
12. What did you test?
13. What did you deliberately not build?
14. How would you deploy it?
15. What would you monitor?
16. What would you change with ten times more data?
17. What would you change with one tenth of the latency budget?
18. How would you secure it?
19. How would you version it?
20. How would you roll back a bad model?
21. What is the most important limitation?
22. What result surprised you?
23. What experiment changed your design?
24. How would you explain the architecture to a non-technical stakeholder?
25. What would you build next?

## How to answer

Use this structure:

**Context → Decision → Evidence → Trade-off → Result → Limitation → Next step**

Do not memorize paragraphs. Use the framework to construct an answer from the actual repository.

## Project-specific preparation

Read each project's README and answer every question without looking at the answer framework. Then open the code and point to the exact function or module that supports your explanation.
