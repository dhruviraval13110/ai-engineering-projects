## Quality rules

- No fake benchmark results.
- No fake production claims.
- No hard-coded secrets.
- Every important transformation has tests.
- Every project documents limitations.
- Experiments are reproducible.
- A notebook is for exploration; reusable logic belongs in modules.
- Metrics are reported with their evaluation context.

## Learning method

**Read → Build → Break → Debug → Test → Measure → Explain → Refactor → Ship**

## Recommended order

Start with Projects 01–03, then move into specialized AI projects. Do not skip the README, tests, or failure-analysis sections.
